## Overview

An analysis and migration plan for a large shared document library. I mapped what was
there, found where it had gone wrong, and designed a new structure with a staged plan
to move to it.

## Context

The library had grown over many years across several sections, with no fixed rules for
naming or for where a record should live.

## Problem

Mapping it showed more than sixty thousand folders. Most tender folders were
duplicated in a second location, the same job number was written in several different
formats, and thousands of file paths were too long to work with reliably.

## Approach

- Mapped every folder and measured the duplication and naming problems.
- Designed a numbered structure with one home for each record.
- Gave every repeated record one fixed ID from the system that owns it, plus a
  readable name, so a spelling change never creates a second copy.
- Kept sensitive staff records in a separate, restricted area.
- Planned the move in batches, logging where each item came from and went to, with
  nothing deleted without sign-off.

## Tools

SharePoint and Excel.

## Status

The analysis and plan were completed as a discussion draft. The move itself did not go
ahead, so the plan was never put into practice.

## What I learned

Most of the effort in a migration goes into the inventory and the rules, well before
anything moves. Uncertain items need an owner and a due date, or they stay uncertain.
